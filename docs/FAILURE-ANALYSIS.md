# RAHBAR Failure Mode Analysis

This document records the empirical fault-injection experiments across the RAG lifecycle for **RAHBAR: Grounded RAG on Kubernetes**. Each stage analyzes what broke, the runtime symptoms, diagnostic observability (logs, metrics, probes), and the remediation procedure.

Per the Track division of responsibility:
- **Track A (Platform & SRE)**: Owns **Stage C (Retrieval / Embedding Pin Guardrail)** and **Stage F (Generation Parameters & Schema Validation)**.
- **Track B (Data & RAG)**: Owns **Stage A (Extraction)**, **Stage B (Chunking)**, **Stage D (Prompting)**, and **Stage E (Source Versioning)**.

---

## Stage C · Retrieval: Embedding Model Mismatch (Track A)

### 1. What We Broke
We introduced an unsynchronized configuration drift between the API and the pre-computed ChromaDB vector index. Specifically, we changed the API ConfigMap to use `EMBED_MODEL: "nomic-embed-text"` without re-indexing the existing Chroma vector store (which remained indexed with `dummy-768`).

### 2. Command to Break It
```bash
# Update ConfigMap or environment variable on API deployment
kubectl set env deployment/api -n rahbar EMBED_MODEL=nomic-embed-text RETRIEVER=chroma
```

### 3. Symptoms Observed
- During a rolling deployment (`kubectl rollout restart deploy/api -n rahbar`), new API pods stay stuck at `0/1 Running` (Not Ready).
- The `/readyz` probe fails with HTTP 503 Service Unavailable.
- The Kubernetes deployment controller stops rollout progress because `maxUnavailable: 0` prevents terminating existing healthy pods until the new replica reports ready. Existing user traffic continues to be served by the old pods without downtime.

```text
[PASTE OUTPUT HERE: kubectl get pods -n rahbar]
Example captured:
NAME                     READY   STATUS      RESTARTS   AGE
api-57cff66495-65z4p     1/1     Running     0          16m
api-774ffb49d6-7shsg     0/1     Running     0          36s
```

### 4. Diagnosis (As If We Had Not Caused It)
1. **Kubernetes Events**:
   ```bash
   kubectl describe pod -l app=rahbar-api -n rahbar
   ```
   *Events log shows:* `Warning Unhealthy 4s (x8 over 44s) kubelet Readiness probe failed: HTTP probe failed with statuscode: 503`.

2. **Application Structured Logs**:
   ```bash
   kubectl logs -l app=rahbar-api -n rahbar --tail=25
   ```
   *Structured JSON log shows exact conflicting model names:*
   ```json
   {"ts": "2026-11-07T13:02:43Z", "level": "ERROR", "logger": "rahbar.health", "msg": "readyz failed: embedding model mismatch", "api_model": "nomic-embed-text", "index_model": "dummy-768", "collection": "rahbar"}
   ```

3. **Direct Probe Execution**:
   ```bash
   kubectl exec -n rahbar pod/<unready-pod> -- python3 -c "import urllib.request, urllib.error
   try: urllib.request.urlopen('http://localhost:8000/readyz')
   except urllib.error.HTTPError as e: print('HTTP', e.code, e.read().decode())"
   ```
   *Output:*
   ```json
   HTTP 503 {"status":"not_ready","failed":"embedding_pin","detail":"Embedding model mismatch: API expects 'nomic-embed-text' but collection metadata records 'dummy-768'"}
   ```

### 5. Root Cause & Impact Analysis
If this mismatch had slipped into production without the Section 4.4 `/readyz` embedding-pin guardrail, user queries embedded by `nomic-embed-text` (768 dimensions) would be compared against vectors generated by a different model (`dummy-768`). Because cosine distance between vectors from differing embedding manifolds is mathematical noise, the vector store would return arbitrary, ungrounded chunks, destroying retrieval quality and hallucinating answers.

### 6. Remedy & Restore Command
Revert the ConfigMap or run a re-indexing Job with the new embedding model before promoting the API rollout:
```bash
# To revert:
kubectl set env deployment/api -n rahbar EMBED_MODEL=dummy-768 RETRIEVER=stub
kubectl rollout status deployment/api -n rahbar
```

## Alternative Stage C · Retrieval: Top-k Starvation (`TOP_K=1`) (Track A)

### 1. What We Broke
Artificially reduced the retrieval depth to a single chunk (`TOP_K=1`), starving multi-hop questions of necessary cross-document context.

### 2. Command to Break It
```bash
kubectl set env deployment/api -n rahbar TOP_K=1
```

### 3. Symptoms Observed
- Multi-part queries (e.g., questions requiring both eligibility criteria and application deadlines) fail to answer fully.
- Questions where the top-1 chunk score falls slightly below `RELEVANCE_FLOOR` trigger immediate false abstentions.

```text
[PASTE OUTPUT HERE: POST /api/ask response with TOP_K=1]
```

### 4. Diagnosis (As If We Had Not Caused It)
- **Structured Logs**:
  Querying the API logs reveals `"top_k": 1`, and `"chunk_ids"` contains only one element.
- **Metrics**:
  `abstentions_total` counter increases significantly in Prometheus `/metrics`.

### 5. Remedy & Restore Command
Restore `TOP_K` to default 5:
```bash
kubectl set env deployment/api -n rahbar TOP_K=5
```

## Stage F · Generation: Temperature Distortion (`TEMPERATURE=1.2`) (Track A)

### 1. What We Broke
Configured the LLM provider to sample at high entropy (`TEMPERATURE=1.2`) rather than deterministic greedy decoding (`TEMPERATURE=0.0` or `0.1`).

### 2. Command to Break It
```bash
kubectl set env deployment/api -n rahbar TEMPERATURE=1.2
```

### 3. Symptoms Observed
- The model produces creative, non-factual assertions ungrounded in the retrieved context.
- The output frequently breaks the required Pydantic `Answer` JSON schema (extra conversational filler, malformed markdown, unclosed braces).
- Pydantic validation fails, triggering fallback behavior or returning HTTP 500.

```text
[PASTE OUTPUT HERE: POST /api/ask response with TEMPERATURE=1.2]
```

### 4. Diagnosis (As If We Had Not Caused It)
1. **Application Logs**:
   ```json
   {"level": "WARNING", "logger": "rahbar.api", "msg": "generation validation failed, triggering fallback", "error": "JSONDecodeError"}
   ```
2. **Prometheus Metrics**:
   A sharp rise in `fallbacks_total` counter on `/metrics`:
   ```text
   # TYPE fallbacks_total counter
   fallbacks_total 12.0
   ```
3. **Evaluation Metrics**:
   Evaluation on the golden dataset reports `citation_validity` plummeting below the acceptable threshold.

### 5. Remedy & Restore Command
Restore temperature to deterministic baseline:
```bash
kubectl set env deployment/api -n rahbar TEMPERATURE=0.0
kubectl rollout status deployment/api -n rahbar
```

## Stage A · Extraction: Unhandled Scanned PDFs and OCR Failure (Track B)

### 1. What We Broke
Ingested scanned image-only PDF documents without Tesseract OCR pre-processing enabled, or fed corrupt PDF streams to `extract.py`.

### 2. Symptoms Observed
- Indexer processes documents but produces zero extracted text characters for entire pages.
- Extracted chunks contain empty strings or pure whitespace.

```text
[PASTE OUTPUT HERE: Track B Indexer extraction failure logs]
```

### 3. Diagnosis (As If We Had Not Caused It)
- Log line in indexer: `{"logger": "rahbar.indexer", "msg": "extracted 0 characters from page 3"}`.
- Chroma collection chunk count is abnormally low.

### 4. Remedy & Restore Command
Ensure system dependencies `tesseract-ocr` and `poppler-utils` are installed in the indexer image, and fallback OCR is triggered when text stream length is below threshold.

## Stage B · Chunking: Oversized Chunks and Boundary Truncation (Track B)

### 1. What We Broke
Configured `CHUNK_SIZE=50` with zero overlap (`CHUNK_OVERLAP=0`), cutting critical sentences and tables mid-token across chunk boundaries.

### 2. Symptoms Observed
- Retrieved chunks contain disjointed fragments lacking syntactic or semantic meaning.
- Embedder fails to capture complete propositional context, causing retrieval recall@k to drop drastically.

```text
[PASTE OUTPUT HERE: Track B Chunk fragmentation output]
```

### 3. Diagnosis (As If We Had Not Caused It)
- Evaluation script `eval/run_eval.py` shows a catastrophic drop in `recall_at_k`.
- Inspection of chunks stored in Chroma reveals truncated sentence fragments without heading hierarchy.

### 4. Remedy & Restore Command
Restore chunking parameters in ConfigMap:
```bash
kubectl set env deployment/api -n rahbar CHUNK_SIZE=800 CHUNK_OVERLAP=150
```
